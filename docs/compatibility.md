## 接入与诊断

本次涉及的主消息/composer DOM、会话输入、持久内容、消息接受、模型和侧栏差异集中在 `src/client/host/`。业务层保留引用来源/目标、fork 生命周期和保存规则。保留有依据的代际分界，不使用版本到类的 adapter registry。

诊断默认关闭，正常使用不显示顶栏诊断按钮或整体受限标记。开发者调试或报告问题时，在 **设置 → 通用设置 → dsh-sidenote 诊断模式** 手动开启，再点击会话顶栏的“兼容诊断”查看或重查当前能力：可用、等待就绪、尚未确认、不可用。选择只保存在当前浏览器、当前 DSH 地址，刷新后保留；浏览器拒绝保存时，设置行会说明仅当前页生效。关闭后立即隐藏面板与按钮，不改变正文、附件、注释或侧聊，不关闭后台能力检测和输入恢复，也不读写宿主全局开发者开关。所有维护组合使用同一个插件开关，不跟随新版宿主缺省开启的开发者模式。

服务尚未提供、会话或 DOM 尚未挂载时不判断为不兼容；明确提供了缺必要方法的接口才记不可用，读取失败记尚未确认。空会话、没有打开侧聊或版本未知不会自动弹出故障提示。消息接受能力只有实际观察到当前会话代际的持久 user/steering 或权威 Queue/Inbox 才确认，不能根据清稿或乐观气泡判断。重新检查只读取状态，不发送测试消息、不创建侧聊或调用模型。

受限时保留已保存注释、正文和附件，并在现有编辑器/chip/输入框显示原因。接口恢复后重查并重试；恢复遇到另一份宿主草稿时保留本地内容，先核对再发送。看不到精确源消息时只隐藏角标，不删除引用或猜另一个会话。

诊断报告只在手动点击“导出报告”时下载，不自动上传；仅含软件版本、能力、原因和接入路径，不包含会话 ID、用户正文、鉴权 URL、Cookie、Key 或本机路径。插件版本由构建清单给出；宿主/组件缺可靠 metadata 时显示未知。完整组件版本由 CI 的实际运行 inventory 记录，不从 devDependencies 或 CLI 推断。

## 验收和新版准入

1. 从官方 dist-tag 选定候选后固定精确版本；安装失败直接报错，不能换测 latest。
2. 隔离 DSH_HOME/profile、工作区、端口，核对实际 CLI、运行组件和当前构建摘要；不升级日常实例。
3. 所有固定组合跑同一套主→主、主→侧、侧→侧、编辑/chip、完整协议、失败重试、恢复/隔离与回流流程。涉及的 Queue/Steer/Stop、busy fork、模型与图片也通过真实宿主链路验证。
4. 辨别安装/宿主故障、插件 API/DOM 适配及测试定位问题，保留原失败，聚焦修复并重跑旧维护组合；不能降低断言或跳过功能。
5. 候选需完成相关完整功能、真实运行和可见浏览器验收后，再通过 PR 更新支持声明、安装范围、双语指南和 required checks；核对 GitHub ruleset 的实际检查名称。

现有五组必需检查保留，新增 `plugin-mount (0.2.0-rc.2, none)`，共六组宿主检查。每周 canary 解析一次 latest，随后固定该版本跑相同流程和 inventory；失败保存证据且在 job 中可见，不自动修改支持范围或用户环境。使用现有 GitHub Actions 状态，不另建通知机器人。

真实输入 Ctrl/Cmd+Enter 的 Steer 遵循宿主步骤边界；停止保留的队列由后续发送继续唤醒。消息被接受和模型回答成功分别记录。
