# 宿主兼容与维护范围

[English](compatibility_EN.md) · 中文

当前开发主线采用 **当前常规版本＋过渡版本＋至多一个预览版本**，所有版本必须完成准入并共用宿主原生 Conversation。常规指 DSH 的 `latest` 发布通道，版本号也可能包含 rc；预览来自 `next`。按角色滚动，不机械选最新三个版本，也不跟随 npm 标签自动扩大支持。

`package.json` 的 `dshSupport` 是已准入角色清单：`current` 为已验收的最新常规版本，`previous` 为上一个已准入常规版本，`preview` 为可选的已准入预览版。版本必须精确且不重复；没有合格预览、或 next 与当前相同时设为 null。若原生能力不足，可通过 PR 将 previous 设为 null 并明确收窄范围，不为凑数量另写聊天界面。公开安装以对应 Release 的声明为准；历史包的兼容范围不会追溯改变。

| 精确宿主 | 当前主线 | 窗口外停留方式 |
|---|---|---|
| DSH 0.2.1-rc.2，不装 BS | 当前常规版本，必需 CI | — |
| DSH 0.2.0-rc.2，不装 BS | 过渡版本，必需 CI | — |
| DSH 0.2.1-rc.3，不装 BS | 已准入预览版，同等必需 CI | 原生支持自 dsh-sidenote 0.7.1 起 |
| DSH 0.1.7-rc.2 / 0.1.5-rc.2，不装 BS | 已退役 | 固定 dsh-sidenote 0.6.5 |
| DSH 0.1.1-rc.2 + BS 0.12.3 / 0.18.0 | 已退役 | 固定 dsh-sidenote 0.6.5 及原 BS 版本 |
| DSH 0.1.2-rc.1 + BS 0.18.0 | 已退役 | 固定 dsh-sidenote 0.6.5 及原 BS 版本 |

0.6.5 包含 @lilongsky 的 V4 回流修复及后续失败确认保护，保留旧界面与已验证的 rc.3 兼容。rc.3 原生准入另行验证，不以旧界面结果替代；原生支持自 0.7.1 起，历史 0.7.0 仍仅支持前两版。rc.3 可运行 `dsh plugin --profile web add --save-exact dsh-sidenote@0.7.1`。

BS 指 dsh-better-sidebar。当前主线不再依赖它；未列出的宿主、alpha 及 BS 共存组合未经验证。

窗口外不再在当前主线保留独立聊天界面，不跑每个 PR 的旧宿主矩阵，也不回补新功能或常规修复。历史 npm 包与 Release 保留；无需给每个宿主建立长期维护分支。若出现必须处理的重大问题，应单独决定补丁范围与发布，不能据此推导无限维护承诺。

## 旧用户如何停留

在旧宿主上固定最后兼容版：

```bash
dsh plugin --profile web add --save-exact dsh-sidenote@0.6.5
```

这会在 profile 写入精确依赖，避免按宽泛依赖范围跨过兼容边界；用户显式换版本属于另一个动作。升级到窗口内宿主后，再安装该宿主兼容的新版插件。

机制分三层：

- **仓库**以 `dshSupport` 维护精确角色清单。`node scripts/host-window.mjs` 校验两处 DSH engines 和 UI primitives peer 与清单一致，并生成 CI 矩阵；不一致即失败。当前范围为 `=0.2.0-rc.2 || =0.2.1-rc.2 || =0.2.1-rc.3`。0.2.0 的校验依赖 DSH peer，只写根 engines 不足以拦截它。
- **npm**保留旧包，`latest` 指向当前发行版。dist-tag 只是版本别名，不按宿主自动选择；不需要下架旧包或另建包名。
- **DSH 安装器／市场**执行兼容检查。0.2.1 市场可从索引中筛选兼容发行版，依赖完整的版本索引；CLI 直接安装不兼容目标会拒绝或恢复旧安装，不承诺遍历 npm 全部历史版本。更早安装器的自动回退不作保证，因此提供上面的固定版本命令。

提高宿主门槛时：发布前确定退出宿主及最后兼容插件版本，同一 PR 更新角色、三处范围与双语指南，CI 自动使用该清单。GitHub 必需检查固定为 ci + host-compatibility，只有门槛结构变化才需调整 ruleset 并回读核对。发布新包后保留旧包。普通功能 PR 不改包版本，版本变更单独走发布 PR。

## 原生聊天复用

主、侧使用宿主同一套 Conversation、SessionProvider、输入框、消息流、队列、命令、文件引用、附件、模型、推理强度、审批及提问界面。插件只增加 fork、继承历史折叠、注释、回流、保存与找回。注释和回流提交仍经过原生输入仲裁与真实接受确认。

侧聊目前嵌入原生对话视图；主会话页面的“轨迹”页签尚未嵌入侧栏。复用聊天界面不代表主会话页面的所有视图入口都已对齐。

接入集中在 `src/client/host/`；两版共有的原生 chat View 和 keyed message 注册条目的装饰保留宿主原渲染器。继承历史筛选、注释锚点、主线快照及会话列表隐藏使用经过固定矩阵验证的运行时槽位边界，并非宿主承诺的长期稳定隐藏 API。无法识别时保留宿主原界面，不能猜测消息来源或投递目标。

侧聊默认隐藏，身份按浏览器及 DSH 地址保存，独立于 Tab 和最近五条关闭菜单；不归档运行中的新版会话。保存会生成完整已完成历史的可见副本，正在运行、提交、有待发队列或未发送的草稿、附件、注释时禁止保存；先发送或清除未发送内容，避免副本没有草稿却关闭源侧聊。设置中的“在会话列表中显示侧边聊天”可找回已登记侧聊；不会恢复删除的会话，也不会自动取消旧版本的归档。

## 接入诊断

诊断默认关闭。在 **设置 → 通用设置 → dsh-sidenote 诊断模式** 开启后，从会话顶栏查看或重查可用、等待就绪、尚未确认及不可用状态。选择仅保存在当前浏览器和 DSH 地址；保存失败时说明仅当前页生效。关闭诊断不影响正常能力检测、失败保留或恢复，也不改变宿主开发者开关。

消息接受必须观察到目标会话的持久 user/steering 或权威 Queue/Inbox，不能仅凭清稿或乐观气泡。重查只读，不调用模型。失败保留正文、附件和注释；接口恢复后可重试。无法定位精确源消息时隐藏角标并保留引用。

报告仅手动下载，不自动上传；仅含软件版本、能力、原因和接入路径，不含会话 ID、正文、鉴权 URL、Cookie、Key 或本机路径。运行组件版本由 inventory 实读，未知时不从 CLI 或 devDependencies 推算。内容搜索仍受宿主结果数上限约束，过滤隐藏侧聊后不补拉结果。

## 验收与滚动准入

每个相关 PR 运行 `ci`、角色清单生成的全部 `plugin-mount` 任务和固定 `host-compatibility` 汇总检查。已准入的预览版也必须通过；ci 或任一宿主失败、取消或跳过都不能放行。各组使用官方安装通道、隔离 DSH_HOME、实际组件版本及当前构建摘要，跑同一套完整用户流程。受控模型用于可重复的排队、停止、拒绝与恢复；官方 Flash lane 单独验证外部模型和真实工具执行，验收报告区分消息接受与模型回答成功。

候选先钉精确版本，完成完整功能、相关真实模型和可见浏览器验收，再通过 PR 更新角色。新 next 通过准入后仅替换 preview，不挤掉 current / previous。新常规版本通过准入并随插件发布后，原 current 转为 previous，原 previous 退出；若新 current 与 preview 重合，preview 清空。每次替换记录退出宿主的最后兼容插件和精确安装命令，不自动下架旧包或向旧版回补新功能。latest / next 是 DSH 的通道，不是本插件 npm 标签；标签变化本身不构成准入或退役。

每周或手动启用 host-canary 时，分别解析一次 latest / next 并记录精确候选；缺少 next 可跳过。未准入候选保存记录并明确报需准入，不绕过安装声明；已准入版本跑完整 journey。canary 不属于 PR 必需门槛，失败可见但不自动改变角色、包声明或用户环境。可通过 Actions 的 workflow_dispatch 勾选 host-canary 手动运行。
