# 宿主兼容与维护范围

[English](compatibility_EN.md) · 中文

当前开发主线维护 **当前基础版本系列**，共用宿主原生 Conversation。系列指去掉预发布后缀后的完整版本，例如 `0.2.1`；不是整个 `0.2.x`。当前系列从最低兼容 RC 开始，允许同系列后续 RC 及无后缀正式版安装，不因 RC 编号增加而淘汰已经支持的版本。alpha、beta 和窗口外系列不自动纳入。

安装范围与验收证据分开：**允许安装不表示该精确版本已经验证**，也不保证尚未发布的 RC 一定兼容。`package.json` 的 `dshSupport` 保存当前系列的 `minimum` 和按版本排序的 `verified` 清单。日常 PR 验收当前系列的最低版与最新已验证版，重复项合并；定期 canary 覆盖中间版本及新增 RC。旧系列由历史 npm 包承接，不在主线保留过渡系列或长期维护分支。

| 系列 | 最低兼容版本 | 已验证的精确版本 | 日常 PR 必需宿主 |
|---|---|---|---|
| 当前：0.2.1 | 0.2.1-rc.2 | rc.2、rc.3、rc.4、rc.5 | 0.2.1-rc.2、0.2.1-rc.5 |

本表对应开发主线。新范围随包含本变更的插件版本发布，不追溯改变已发布的 0.7.6 或其他历史包；公开安装以对应 Release 和包声明为准。同系列未来 RC 默认允许安装，但在验收前不加入 `verified`。

| 窗口外宿主 | 停留方式 |
|---|---|
| DSH 0.2.0-rc.2 | 固定 dsh-sidenote 0.7.6 |
| DSH 0.1.7-rc.2 / 0.1.5-rc.2，不装 BS | 固定 dsh-sidenote 0.6.5 |
| DSH 0.1.1-rc.2 + BS 0.12.3 / 0.18.0 | 固定 dsh-sidenote 0.6.5 及原 BS 版本 |
| DSH 0.1.2-rc.1 + BS 0.18.0 | 固定 dsh-sidenote 0.6.5 及原 BS 版本 |

0.6.5 包含 @lilongsky 的 V4 回流修复及后续失败确认保护，保留旧界面与已验证的 rc.3 兼容。rc.3 原生支持自 0.7.1 起，历史 0.7.0 不支持。BS 指 dsh-better-sidebar；当前主线不依赖它，BS 共存组合未经验证。

窗口外不再在当前主线保留独立聊天界面，不跑每个 PR 的旧宿主矩阵，也不回补新功能或常规修复。历史 npm 包与 Release 保留；重大问题单独决定补丁范围，不为每个宿主建立长期维护分支。

## 旧用户如何停留

在 DSH 0.2.0-rc.2 上固定最后兼容版：

```bash
dsh plugin --profile web add --save-exact dsh-sidenote@0.7.6
```

更早的 0.1 宿主按上表固定 0.6.5。这会在 profile 写入精确依赖，避免按宽泛依赖范围跨过兼容边界。升级到窗口内宿主后，再安装该宿主兼容的新版插件。

机制分三层：

- **仓库**以 `dshSupport` 记录系列下限与已验证版本。`node scripts/host-window.mjs` 校验两处 DSH engines、UI primitives peer 与系列范围一致，并生成精确 CI 矩阵；`--all` 输出全部已验证版本。当前范围为 `>=0.2.1-rc.2 <0.2.2-0`，上界排除下一系列的所有预发布版。0.2.0 的校验依赖 DSH peer，只写根 engines 不足以拦截它。
- **npm**保留旧包，`latest` 指向当前插件发行版。dist-tag 是版本别名，不按宿主自动选择，不需要下架旧包或另建包名。
- **DSH 安装器／市场**执行包中声明的范围。0.2.1 市场可从完整索引筛选兼容发行版；CLI 直接安装不兼容目标会拒绝或恢复旧安装，不承诺遍历 npm 全部历史版本。更早安装器的自动回退不作保证。

系列滚动时，新系列必须完成完整功能、相关真实模型及可见浏览器验收，再通过 PR 更新清单、三处范围和双语指南，并随插件发布生效。原系列停止维护；退出时记录最后兼容插件和精确安装命令。新 alpha 或 npm 标签漂移不会触发退役。日常功能 PR 不改插件版本，版本变更走独立发布 PR。

## 原生聊天复用

主、侧使用宿主同一套 Conversation、SessionProvider、输入框、消息流、队列、命令、文件引用、附件、模型、推理强度、审批及提问界面。插件只增加 fork、继承历史折叠、注释、回流、保存与找回。注释和回流提交仍经过原生输入仲裁与真实接受确认。

侧聊目前嵌入原生对话视图；主会话页面的“轨迹”页签尚未嵌入侧栏。复用聊天界面不代表主会话页面的所有视图入口都已对齐。

接入集中在 `src/client/host/`；窗口内宿主共有的原生 chat View 和 keyed message 注册条目的装饰保留宿主原渲染器。继承历史筛选、注释锚点、主线快照及会话列表隐藏使用经过固定矩阵验证的运行时槽位边界，并非宿主承诺的长期稳定隐藏 API。无法识别时保留宿主原界面，不能猜测消息来源或投递目标。

侧聊默认隐藏，身份按浏览器及 DSH 地址保存，独立于 Tab 和最近五条关闭菜单；不归档运行中的新版会话。保存会生成完整已完成历史的可见副本，正在运行、提交、有待发队列或未发送的草稿、附件、注释时禁止保存；先发送或清除未发送内容，避免副本没有草稿却关闭源侧聊。设置中的“在会话列表中显示侧边聊天”可找回已登记侧聊；不会恢复删除的会话，也不会自动取消旧版本的归档。

## 接入诊断

诊断默认关闭。在 **设置 → 通用设置 → dsh-sidenote 诊断模式** 开启后，从会话顶栏查看或重查可用、等待就绪、尚未确认及不可用状态。选择仅保存在当前浏览器和 DSH 地址；保存失败时说明仅当前页生效。关闭诊断不影响正常能力检测、失败保留或恢复，也不改变宿主开发者开关。

消息接受必须观察到目标会话的持久 user/steering 或权威 Queue/Inbox，不能仅凭清稿或乐观气泡。重查只读，不调用模型。失败保留正文、附件和注释；接口恢复后可重试。无法定位精确源消息时隐藏角标并保留引用。

报告仅手动下载，不自动上传；仅含软件版本、能力、原因和接入路径，不含会话 ID、正文、鉴权 URL、Cookie、Key 或本机路径。运行组件版本由 inventory 实读，未知时不从 CLI 或 devDependencies 推算。内容搜索仍受宿主结果数上限约束，过滤隐藏侧聊后不补拉结果。

## 验收与滚动准入

每个相关 PR 运行 `ci`、当前系列最低版与最新已验证版的全部 `plugin-mount` 任务，以及固定 `host-compatibility` 汇总。失败、取消或跳过均不放行；required checks 仍为 ci + host-compatibility。窗口滚动不改变检查名，门槛结构变化时同步并回读实际 ruleset。

每日 canary 一次读取 npm 的版本清单和 latest / next 标签，按同一系列范围筛选候选，去重后对每个尚未记入 `verified` 的已发布 RC／正式版、当前系列最新已发布版及窗口内通道目标运行完整 journey。这样不会漏掉两次探测之间已被新标签替代的 RC。每周一及手动启用 host-canary 时，回归窗口内全部已发布的 RC／正式版，包括中间版本。latest / next 指向窗口外系列时保存候选并明确失败提示准入，同时继续验证窗口内宿主；缺少 next 可跳过。

每组使用官方安装通道、隔离 DSH_HOME、实际组件版本与当前构建摘要。受控模型验证队列、停止、拒绝、恢复及主侧隔离；官方 Flash lane 单独验证外部模型和真实工具执行。报告区分消息接受与模型回答成功。新版本通过完整功能、相关真实模型及可见浏览器验证后，通过 PR 写入 `verified`；canary 不自动写验收记录、不发布插件、不升级用户环境，也不属于每条 PR 的必需门槛。

同系列未来 RC 可以在验证完成前安装；遇到真实接口破坏时补适配，必要时通过 PR 收窄范围并写明受影响版本。测试只对实际运行过的版本提供证据，最低版／最新版检查不能代替中间版本的准入与定期回归。`pnpm test:compat` 验证当前兼容构建遭遇不兼容更新时恢复原包；系列退役时另外验证旧宿主拒绝本次新构建，并恢复历史包的精确依赖、包声明和客户端／服务端字节；不把旧宿主继续列入日常功能矩阵。先运行 `pnpm build && pnpm pack`，本次退役检查为：

```bash
DSH_CMD="npx -y --package @deepseek-ai/dsh@0.2.0-rc.2 dsh" \
DSH_COMPAT_BASELINE=dsh-sidenote@0.7.6 \
DSH_COMPAT_REJECTED="file:$PWD/dsh-sidenote-$(node -p 'require("./package.json").version').tgz" \
pnpm test:compat
```
